## Project structure

Create one Railway project per environment. Each project contains:

1. **Backend service** — Django API
2. **Frontend service** — Vite static site
3. **Collab service** — Node.js WebSocket server
4. **PostgreSQL** — Railway Postgres plugin

Connect the Railway project to the `paulvanderheijden/vector` GitHub repository. Each service uses a different root directory from the same repo.

## PostgreSQL

Add the Railway Postgres plugin to the project. Railway auto-injects `DATABASE_URL` as a variable available to all services.

Reference it in both backend and collab services using Railway's variable references:

```
DATABASE_URL = ${{Postgres.DATABASE_URL}}
```

## Backend service (Django)

### Settings

| Setting | Value |
|---|---|
| Root directory | `/backend` |
| Build command | `pip install -r requirements.txt && python manage.py collectstatic --noinput && python manage.py migrate` |
| Start command | `gunicorn vector.wsgi:application --bind 0.0.0.0:$PORT` |

<Note>
  `gunicorn` must be added to `requirements.txt` before deploying. It is not included in the current development dependencies.
</Note>

### Environment variables

| Variable | Value | Notes |
|---|---|---|
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` | Auto from Railway Postgres plugin |
| `SECRET_KEY` | (generate a strong random key) | Used for Django signing and JWT |
| `DEBUG` | `False` | Always `False` in deployed environments |
| `ALLOWED_HOSTS` | `*.up.railway.app,vector.app` | Comma-separated, include custom domains |
| `FRONTEND_URL` | `https://vector.up.railway.app` | Used for CORS `Access-Control-Allow-Origin` |
| `RESEND_API_KEY` | (from Resend dashboard) | For transactional emails |

### Static files

The backend uses **WhiteNoise** (already in `requirements.txt`) to serve static files. `collectstatic` runs as part of the build command.

## Frontend service (Vite)

### Settings

| Setting | Value |
|---|---|
| Root directory | `/frontend` |
| Build command | `npm install && npm run build` |
| Output directory | `dist` |

Railway's Nixpacks builder detects the Vite project and serves the `dist` folder as a static site.

### Environment variables

| Variable | Value | Notes |
|---|---|---|
| `VITE_API_URL` | `https://vector-api.up.railway.app` | Backend's public URL (no trailing slash) |
| `VITE_COLLAB_WS_URL` | `wss://vector-collab.up.railway.app` | Collab's public URL, must use `wss://` |

<Warning>
  Vite environment variables are **build-time only**. They are baked into the JavaScript bundle during `npm run build`. Changing them requires a redeploy.
</Warning>

### Code change required

The frontend's Axios client (`src/lib/api.ts`) must read the API URL from the environment:

```typescript
const API_BASE = import.meta.env.VITE_API_URL ?? "http://localhost:8000"
```

This allows the same codebase to work locally (fallback to `localhost:8000`) and in Railway (reads the injected `VITE_API_URL`).

## Collab service (Node.js)

### Settings

| Setting | Value |
|---|---|
| Root directory | `/collab` |
| Build command | `npm install && npm run build` |
| Start command | `npm start` |

The start command runs `node dist/server.js` (defined in `package.json`).

### Environment variables

| Variable | Value | Notes |
|---|---|---|
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` | Same Postgres instance as backend |
| `JWT_SECRET` | `${{backend.SECRET_KEY}}` | Must match backend's `SECRET_KEY` for JWT validation |
| `PORT` | (auto from Railway) | Railway injects this automatically |

## Custom domains

For production, configure custom domains in Railway's service settings:

| Service | Domain |
|---|---|
| Frontend | `app.vector.com` |
| Backend | `api.vector.com` |
| Collab | `collab.vector.com` |

Add the domains to the backend's `ALLOWED_HOSTS` and update `FRONTEND_URL`, `VITE_API_URL`, and `VITE_COLLAB_WS_URL` accordingly.

## Health checks

Configure Railway health checks for the backend and collab services:

| Service | Health check path | Protocol |
|---|---|---|
| Backend | `/api/v1/health/` | HTTP |
| Collab | (none — WebSocket server) | TCP |
